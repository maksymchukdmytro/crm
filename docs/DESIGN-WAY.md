# Як ми працюємо над дизайном CRM

Цей файл — для власника й для кожної нової сесії Claude. Тут записано, як ми дійшли до нинішнього вигляду, що
власник цінує і як читати його короткі повідомлення. Прочитати **перед** будь-якою роботою над інтерфейсом, разом з
`docs/UI-DESIGN.md` (правила й токени) і `docs/UI-NEXT.md` (що робити далі).

---

## 1. Цикл, який працює

1. **Власник показує проблему.** Здебільшого скриншот з однією фразою («ось тут не добре», «криво», «баг інтерфейсу»)
   або коротке побажання. Скриншот без тексту означає «тут вада, знайди й виправ».
2. **Макети, не код.** На «відмалюй», «запропонуй варіанти» відповідь — 3–5 варіантів картинками
   (`docs/design/mockups/`, `python3 render.py <модуль>`). Кадр ПК 1440×900, телефон 390×844. На кадрі — рожеві номери,
   праворуч пояснення: що змінилось і навіщо. Для мобільних правок — пара «Зараз» (справжній скриншот) → «Стане».
3. **Власник обирає.** «Варіант C — найкращий, його і робимо». Обраний варіант — закон: інші ідеї з нього не тягнути.
4. **Впровадження — на ПК і телефоні одразу** (якщо не сказано інше). Поетапно: гілка `wip/ui-…` → CI (збірка,
   тести) → скриншоти → злиття в `main` → сервер підхоплює сам. Після кожного етапу — 1–2 речення, що вийшло.
5. **Перевірка, як у користувача.** Стрес-база (~2 650 замовлень) і повний прохід зі скриншотами
   (`scripts/ui-check/`): помилки JS/API, прокрутка вшир, дрібні цілі дотику, швидкість. Звіт: що було не так, що
   змінив, що рекомендую. Знахідки виправляти одразу, а не лише описувати.

## 2. Як читати повідомлення власника

| Каже | Означає |
|---|---|
| «відмалюй N варіантів», «запропонуй і відмалюй» | Лише макети картинками з поясненнями. Код не чіпати. |
| «впроваджуй», «роби», «робимо» | Код для ПК і телефону, з тестами, викласти на сервер. |
| «роби всі, поступово» | Усі пункти, етапами; кожен етап окремо злити й викласти. |
| «не роби, додай у план» | Лише документи (`ROADMAP.md`, `UI-NEXT.md`), без коду. |
| «прожени стрес-тест», «пройдись» | Стрес-база + повний прохід ПК і телефону, скриншоти, звіт із цифрами. |
| «як скрізь», «як ми робили раніше» | Той самий компонент, що вже є (меню — `Select`/`Popover`, підказки — `HoverCard`, порожні сторінки — `EmptyState`). Не вигадувати новий. |
| «криво», «не сучасно», «не видно нічого» | Візуальна вада. Спершу перевірити на поточній збірці (часто скриншот старий), потім виправити й показати скриншот. |
| «щоб більше поміщалось» | Щільніше: менші відступи, менше колонок тексту, значки з підказкою — але цілі дотику на телефоні ≥ 44 px. |
| «Стоп, зачекай» | Негайно зупинитись, нічого не зливати, сказати, в якому стані робота. |

Мова — завжди українська: інтерфейс, коментарі, коміти, відповіді.

## 3. Що власник цінує (накопичені рішення)

**Загальний вигляд**
- Сірий фон, **білі картки без рамок** (ПК 18 px, телефон 20 px), кольорові квадрати-іконки (`sq`), кільця для
  відсотків і часу очікування. Пласко, без тіней на кожному блоці, без градієнтів, **без емодзі** (іконки — лише lucide).
- **Статус — своїм кольором** скрізь: таблетка, вкладка, крапка. Поточна вкладка «Усі» — темна.
- **Одна синя головна дія** на екрані. Окремого «Зберегти» немає — усе зберігається само («Збережено» в шапці).
- **Телефон — першим**: у формах спершу номер, потім ім'я (покупець підставляється сам).
- **Меню вибору — однакові всюди й не системні** (31.10: «вигляд контекстного меню має бути як скрізь, гарний»).
  03.11: так само мають виглядати **галочки, кольори, календарі, вікна підтвердження** — див. `UI-NEXT.md`, етап A.
- **Простір — для головного.** Текстом лише те, що читають щоразу (№, покупець, товар, статус, сума, дата). Телефон,
  доставка, оплата, джерело — **значком з підказкою при наведенні** (03.11, «телефон показувати значком»).
- Нічого не обрізати й не виносити за край: на 375–390 px немає прокрутки вшир, на 1280 px таблиця вміщається.
- Порожні сторінки — з поясненням і кнопкою дії (`EmptyState`).
- Дрібне, але важливе: правильні відмінки («4 замовлення»), дати по-людськи («учора», «28.10»), гроші з пробілами.

**Конкретні рішення, які не переглядати без власника**
- Картка замовлення — **варіант C** (31.10): ліворуч кроки картками Покупець → Товари → Оплата | Доставка, праворуч
  сума з однією синьою дією, деталі (Джерело | Менеджер, Відділ | Юрособа, коментар на всю ширину; «Поля 1–4» і UTM
  згорнуті), коротка історія. Товари — найбільший блок, рядок товару низький.
- Нове замовлення — **покроковий майстер, варіант A** (31.10): Покупець (з джерелом) → Товар → Оплата → Деталі →
  Доставка останньою; «Створити й оформити ТТН» одразу відкриває вікно ТТН.
- Список замовлень на ПК (03.11, макети v20): **Таблиця · Картки (щільніші за макет) · Скринька · Дошка**.
- Мобільна версія v2 (30.10): велика назва розділу, круглі кнопки, нижня панель-острівець із синім «+», картки 20 px.
  Темна плитка «Продано сьогодні» на мобільній головній — погоджений виняток із правила «без чорних панелей».

(догрузка, підвисання, обрізані колонки).

## 5. Технічні опори стилю

- Токени й базові стилі — `frontend/src/ui.css`; оболонка — `shell.css`; списки — `list.css`, `orders.css`;
  картка — `card.css`; майстер і ТТН — `wizard.css`; телефон — `mobile.css` (лише до 768 px).
- Компоненти (`components/ui/`): `Select`, `SelectPick`, `HoverCard` / `Floating` (підказки й меню поверх таблиць),
  `DenseTable` (віртуалізація, мобільні картки), `Tabs` (кольорові), `Segmented`, `StatusPill`, `Ring`, `EmptyState`,
  `Window`, `Sheet`, `SidePanel`, `BulkBar`, `ChipSelect`, `Toggle`.
- **Пастка:** зайва дужка `}` у CSS тихо вимикає наступне правило (03.11 так «зламалась» палітра Ctrl K). Після правок
  CSS — перевірка балансу дужок (скрипт у `scripts/ui-check/README.md`).
- Фронтенд локально не збирається (неповний `node_modules`): збирає CI, артефакт `frontend-dist` →
  `gh run download <id> -n frontend-dist -D frontend/dist`.

## 6. Чекліст перед тим, як показати власнику

- [ ] ПК 1280 і 1440(+1920) і телефон 390: скриншоти, нічого не обрізано, немає прокрутки вшир.
- [ ] Немає системних елементів (`select`, `checkbox`, `date`, `color`, `confirm`) — лише компоненти CRM.
- [ ] Одна синя дія, статуси своїм кольором, значки lucide, без емодзі.
- [ ] Цілі дотику на телефоні ≥ 44 px, видимий фокус, контраст ≥ 4,5:1.
- [ ] Помилок JS/API немає (прохід `walk.py`), на стрес-базі швидко.
- [ ] Відмінки, дати, гроші — по-людськи, українською.
- [ ] Тести зелені, CI зелений, у `main` злито, `https://mdmy.me/crm/healthz` показує новий коміт.

## 7. Як почати нову сесію швидко

Достатньо написати, наприклад:

> «Прочитай `docs/DESIGN-WAY.md` і `docs/UI-NEXT.md`. Роби етап A, поступово.»
>
> «Відмалюй 3 варіанти сторінки … (ПК і телефон), як ми робимо, з номерами й поясненнями.»

Claude має: прочитати ці два файли і `CLAUDE.md`; підняти локальне середовище (`scripts/ui-check/README.md`); працювати
циклом із розділу 1; після кожного етапу коротко звітувати, наприкінці — стрес-тест і скриншоти.
