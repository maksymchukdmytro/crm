# Новий інтерфейс CRM — ТЗ і рішення власника

Єдине джерело правди для переробки інтерфейсу. Тут зібрано все, що власник погодив у
розмовах 29–30.10.2026: розкладку, правила вигляду й поведінку кожної сторінки. Макети лежать у
`docs/design/screens/`, а генератори макетів — у `docs/design/mockups/` (див. кінець файлу).

Порядок дій для нової сесії:
1. Прочитати цей файл повністю.
2. Відкрити макет потрібної сторінки.
3. Звірити його з розділом нижче. Якщо макет і текст розходяться, правильний текст.

Що з цього вже зроблено в коді, позначається в `docs/ROADMAP.md` (розділ «Новий інтерфейс»).
Технічна частина (база, міграції, API, сервіси, тести) — окремим файлом **`docs/UI-TECH.md`**.

## 1. Головні рішення (коротко)

| Тема | Рішення |
|---|---|
| Стиль | Чистий: світлий фон `#F7F7F5`, білі блоки, тонкі лінії, шрифт **Onest**, іконки лише **lucide**. Без емодзі, градієнтів і тіней на кожному блоці. |
| Чорний | **Чорних плашок і панелей немає.** Темний колір має лише поточний статус (пігулка в шапці картки й активна вкладка списку). |
| Акцент | Синій `#2E6BE6`. На екрані одна синя кнопка головної дії. Блок підсумку — світло-синій, не чорний. |
| Заокруглення | Те, що натискають, — **пігулки**. Те, куди вводять, — **8 px**. Блоки — **14 px**. Вікна — **18 px** (див. 2.3). |
| Списки | Щільна стрічка, як у Notion: рядок **31 px**, один рядок тексту, групи за днями. |
| Картки записів | Замовлення, товар, покупець і налаштування відкриваються **великим вікном поверх списку**, а не окремою сторінкою. |
| Картка замовлення | Дві колонки 4/12 + 8/12. Ліворуч Покупець → Оплата → Доставка, праворуч Товари, під ними Деталі й Підсумок. Історія — під значком. Нижньої панелі й кнопки «Наступний крок» немає. |
| Ліди | Окремий розділ, **вмикається в налаштуваннях**. Має вигляди Стрічка, Дошка й Передзвони. Форми замовлення сховані за кнопкою «Створити замовлення». |

| Видаткові накладні | Новий розділ: усі документи, юрособа в кожному рядку, три кнопки документів. Документи зберігаються в базі. |

## 2. Візуальна мова

### 2.1 Токени (CSS-змінні)

```css
--ink: #1F1F1C;      /* основний текст */
--muted: #6F6E69;    /* другорядний текст */
--faint: #A3A29D;    /* підписи, заглушки */
--line: #ECECE9;     /* лінії й рамки */
--bg: #F7F7F5;       /* фон сторінки й бокової панелі */
--soft: #F2F2EF;     /* плитки, фон фото */
--accent: #2E6BE6;  --accent-soft: #EAF1FD;  --accent-line: #C9DBFA;
--ok: #16A34A;  --ok-soft: #E9F6EE;
--warn: #D97706; --warn-soft: #FDF1E3;
--bad: #DC2626;  --bad-soft: #FDECEC;
```
Темний колір `--ink` як фон дозволений лише для пігулки поточного статусу й активної вкладки.
Акцент і темна тема змінюються лише через токени.

### 2.2 Шрифт
- **Onest** 400 / 500 / 600 для всього тексту, **JetBrains Mono** для номерів, артикулів і ТТН.
- Розміри:
  - заголовок сторінки — 22 px;
  - заголовок вікна — 19 px;
  - заголовок блоку — 15 px;
  - текст — 13–13,5 px;
  - текст у щільних списках — 12,5 px;
  - підписи — 11,5–12 px.
- Великі числа (суми, KPI) — 600, з трекінгом −0,02em.
- Без великих літер у підписах і без підписів-«надголовків» над кожним блоком.

### 2.3 Правило заокруглень
За формою елемента видно, що з ним робити:

| Що | Радіус | Приклади |
|---|---|---|
| Натискають | пігулка (`999px`), кругла для кнопок-іконок | кнопки, статуси, вкладки, сегменти, фільтри-чипи, позначки, пункти меню, перемикачі, телефон покупця |
| Вводять | 8 px | поля, списки вибору, пошук, багаторядкові поля |
| Блоки | 14 px | картки-блоки, таблиці, панель масових дій, випадні списки (12) |
| Вікна | 18 px | вікна замовлення, товару, покупця, налаштувань, ТТН |

### 2.4 Статуси
Статус — пігулка з крапкою: фон — колір статусу на 11 %, текст — той самий колір, затемнений.
Кольори задаються в налаштуваннях. Типові:

| Статус | Колір |
|---|---|
| Несортований | `#7C7B76` |
| Прийнятий | `#2E6BE6` |
| Відправлений | `#6D5BD0` |
| Очікує на отримання | `#D97706` |
| Завершений | `#16A34A` |
| Відмова на пошті | `#E11D48` |
| Повернуто на склад | `#64748B` |
| Відмова | `#DC2626` |

Ліди мають три статуси: Новий (синій), Недодзвон (`#D97706`), Передзвонити (`#7C3AED`).

### 2.5 Доступність
- Контраст тексту ≥ 4,5 : 1.
- Фокус з клавіатури видно завжди: кільце 2 px `--accent` з відступом 2 px.
- Колір ніколи не єдиний носій сенсу: у статусу є назва.
- Цілі дотику на телефоні ≥ 44 px, без прокрутки вшир на 375 px.
- Переходи 150–200 мс, з урахуванням `prefers-reduced-motion`.
- Тексти звичайним регістром. Кнопка називає дію («Створити ТТН»), і та сама дія скрізь зветься однаково.
- Помилка каже, що сталося і як виправити.

## 3. Каркас

Макет: будь-яка сторінка з `screens/`, наприклад `04-holovna.png`.

- **Бокова панель** 236 px на фоні `--bg`, без рамки.
  - Вгорі логотип mdmy, під ним перемикач відділу на всю ширину («Відділ: Інтернет-магазин ▾»). Відділ обмежує все: списки, лічильники, статистику.
  - Групи пунктів:
    - **Продажі** — Головна, Ліди (лише коли розділ увімкнено), Замовлення, Видаткові накладні, Дошка, Покупці;
    - **Склад** — Товари, Склад, Закупівлі;
    - **Гроші й аналітика** — Оплати, Статистика, Звіти;
    - **Керування** — Журнал дій, Налаштування, Система.
  - Пункт — пігулка 32 px. Активний — білий з тонкою рамкою, іконка синя.
  - Лічильники: сірі — для довідки; сині — лише в «Лідах» (нові ліди) і «Замовленнях» (несортовані).
  - Збережені фільтри — кольорова мітка, назва, кількість («Чекають ТТН», «Передзвонити сьогодні»).
  - Внизу користувач: аватар, ім'я, роль.
  - На екранах вужчих за 1280 px панель згортається до смуги іконок 64 px.
- **Верхня смуга** 48 px:
  - пошук «Шукати замовлення, телефон, ТТН або товар…» з підказкою Ctrl K; результати групами Замовлення, Покупці, Товари, Дії;
  - справа круглі кнопки: коментарі для колег і сповіщення.
- **Робоча область** — білий блок з радіусом 18 і відступами 22–24 px.
- **Кнопка «+»** — кругла, 54 px, у правому нижньому куті.
  - Клік створює нове замовлення. Наведення або довге натискання відкриває 5 дій: Нове замовлення (N), Новий лід (L, якщо ліди увімкнено), Товар (P), Покупець (C), Знайти за ТТН (T).
  - Кнопка ховається, коли вибрано рядки або відкрито запис.
- **Панель масових дій** з'являється знизу, коли вибрано рядки.
  - Біла, 50–56 px, радіус 14, по центру робочої області.
  - Зліва «Вибрано 3»; далі: Статус ▾, Менеджер ▾, Наклейки, Реєстр НП, Фіскалізувати, Зняти. Справа синя дія («Створити 3 ТТН»).

## 4. Списки: загальні правила

Макет: `05-zamovlennia.png`.

### 4.1 Щільна стрічка (як Notion)
- **Шапка сторінки в один рядок.**
  - Зліва: заголовок 22 px і поруч підсумок («9 несортованих · 31 чекають відправки · 57 у дорозі»).
  - Справа: перемикач вигляду (Стрічка / Дошка), Колонки, Експорт.
- **Вкладки статусів** — пігулки з лічильниками. Активна — темна. Акцентний лічильник лише в «Несортованих». Вкладки, що не вмістились, ховаються в «Ще».
- **Фільтри-чипи** з пунктирною рамкою «+ Менеджер». Активний фільтр — синій із хрестиком. Фільтри пишуться в адресу сторінки. Справа — пошук у списку.
- **Рядок.**
  - Висота 31 px, текст 12,5 px, усе в один рядок; довгий текст обрізається трикрапкою, повний — у підказці.
  - Шапка таблиці — 32 px, рядок-група за днем — 30 px: «Сьогодні, 29 жовтня · 10 замовлень · 12 316 ₴».
  - На екрані 1440 × 900 має вміщатися 20+ рядків.
- **Колонки** користувач вмикає й перетягує; вибір зберігається для нього.
- **Наведення на рядок** показує справа дії іконками: подзвонити, наклейка, перегляд.
- **Клік по рядку** відкриває вікно запису. Клік у квадратик або пробіл вибирає рядок, Shift-клік — діапазон.
- **Порожній стан** — з дією («Скинути фільтр»). Під час завантаження — сірі рядки-заглушки.

### 4.2 Замовлення
Вкладки, по черзі: **Несортовані · Прийнятий · Відправлений · Очікує на отримання · Завершений ·
Відмова на пошті · Повернуто на склад · Відмова · Усі**.

| Статус | Що означає | Хто ставить |
|---|---|---|
| Несортований | нове з сайту, маркетплейсу, форми або введене вручну; ще не перевірене | CRM при імпорті |
| Прийнятий | перевірено, товар зарезервовано | менеджер («Прийняти» або «Створити замовлення» з ліда) |
| Відправлений | ТТН створена, посилка в дорозі | CRM за трекінгом |
| Очікує на отримання | у відділенні або поштоматі | CRM за трекінгом |
| Завершений | забрали, гроші отримано | CRM за трекінгом |
| Відмова на пошті | не забрали, посилка їде назад | CRM за трекінгом |
| Повернуто на склад | посилку отримано назад, товар повернуто на залишок | склад |
| Відмова | скасовано до відправки, з причиною | менеджер |

- **Колонки за замовчуванням:** ☐ · № · Покупець (+ позначки VIP / Дубль? / Чорний список) · Телефон · Товар (+1) ·
  Статус · Оплата (крапка + назва) · Доставка (служба, місто, стан ТТН кольором) · Джерело · Менеджер (ініціали) ·
  Час · Сума · Перевірка оплати (✓ / ✗ / годинник — чи ТТН відповідає виду оплати, вже працює).
  Замовлення з нагадуванням, час якого настав, має дзвіночок біля номера.
- **У вкладці «Несортовані»:**
  - найстаріші вгорі;
  - попередження (дубль, чорний список, товару немає) — прямо в рядку;
  - при наведенні — кнопка «Прийняти», масова дія — «Прийняти вибрані».
- **Робочі списки** — збережені фільтри зі своїми колонками:
  - «До відправки сьогодні» — колонка «Готовність» з 5 іконок: Резерв, ТТН, Наклейка, Чек, Реєстр;
  - «Потребує уваги».

### 4.3 Ліди (розділ вмикається)
Макети: `06-lidy-strichka.png` і `07-lidy-doshka.png`.

**Два режими роботи CRM.** Перемикач — «Налаштування → Загальні → Розділ Ліди».

| Режим | Для кого | Шлях заявки |
|---|---|---|
| З лідами | лендинги, форми, реклама: покупцеві треба подзвонити | заявка → Ліди → дзвінок → «Створити замовлення» → Замовлення · Прийнятий |
| Готові замовлення | сайт з кошиком, Rozetka, Prom | замовлення → Несортовані → перевірка → Прийнятий |

- **Якщо розділ вимкнено,** пункт меню, лічильник, статуси лідів і «Новий лід» зникають. Заявки з форм ідуть у «Несортовані».
- **Якщо вимикають розділ, де є відкриті ліди,** CRM питає: «12 відкритих лідів — перенести в Несортовані?».

**Вигляди:**
- **Стрічка** (як замовлення):
  - вкладки: Відкриті · Нові · Недодзвон · Передзвонити · Дублі · Відмова ліда · Створено замовлення · Усі;
  - колонки: ☐ · № Л-2047 · Ім'я · Телефон · Товар з форми · Сума · Статус · Чекає · спроба (таймер кольором) · Джерело · Менеджер · дія;
  - вгорі ті, хто чекає найдовше; ліди «Передзвонити» піднімаються, коли настає час.
- **Дошка** — колонки Новий, Недодзвон, Передзвонити, Дубль.
  - Картка **58 px**: ім'я й сума першим рядком; мітка джерела, товар і час очікування — другим.
- **Передзвони** — сьогоднішні дзвінки за годинами.

**Час очікування:**
- до 5 хв — звичайний;
- 5–15 хв — `--warn`;
- понад 15 хв — `--bad`.

Пороги задаються в налаштуваннях. «Передзвонити» показує час дзвінка фіолетовим.

**Статуси ліда:**

| Статус | Що робить CRM |
|---|---|
| Новий | шукає покупця, дублі й чорний список, запускає таймер |
| Недодзвон | SMS «Не додзвонились», нагадування через 30 хв, лічильник спроб |
| Передзвонити | ставить справу на вибраний час |
| Дубль | дає посилання на перший лід чи замовлення |
| Відмова ліда | бере причину з довідника |
| Створено замовлення | дає посилання на замовлення; лід зникає з дошки |

**Вікно ліда** — те саме вікно, що й у замовлення:
- зліва черга дзвінків 280 px;
- у центрі Контакт, Запит (товар і ціна з лендингу, відповіді форми, UTM) і Дзвінки;
- замість Товарів, Оплати й Доставки — пунктирна плашка «+ Створити замовлення». Після кліку вона розгортається в ті самі блоки, що й у картці замовлення, уже заповнені з ліда.

Результати дзвінка: Недодзвон F1 · Передзвонити F2 · Відмова F3 · Дубль. Головна дія — «Створити
замовлення» (Ctrl ⏎): створює замовлення зі статусом **Прийнятий** і відкриває наступний лід.
Відкрите питання: чи має замовлення з ліда йти в «Несортовані».

## 5. Картка замовлення

Макети: `01-kartka-do-ttn.png` (до ТТН, компактні товари) і `02-kartka-pislia-ttn.png` (після ТТН).
Вікно для створення ТТН — `03-vikno-ttn.png`.

### 5.1 Вікно
- **Розмір:** весь екран мінус 16–40 px з боків, не ширше 1480 px, радіус 18. Список позаду затемнений на 36 %.
- **Адреса** `/orders/1482` — нею можна поділитися. Кнопка «Назад» браузера й Esc закривають вікно.
- **Інші замовлення:** J / K — наступне й попереднє зі списку. Нове замовлення відкривається порожнім, з фокусом на телефоні.
- **Збереження** автоматичне:
  - через 0,8 с після введення; Ctrl S — одразу;
  - стан показується біля кнопки: «Зберігаю…» → «Збережено»;
  - «Створити ТТН», «Друк» і «Чек» спершу самі зберігають замовлення.

### 5.2 Шапка
- Зліва ← і **доріжка статусів пігулками**: Несортоване — Прийнятий — Відправлений — Очікує на отримання — Завершений — «⋯».
  - Пройдені статуси сірі, поточний темний з ✓, майбутні білі.
  - Клік по пігулці змінює статус. Якщо статус запускає дії (резерв, чек, SMS), вони показуються в підтвердженні.
  - Відмова на пошті, Повернуто на склад і Відмова — у «⋯»; у такому статусі доріжка відгалужується червоною пігулкою.
- Справа: **Друк ▾** (видані документи з галочкою) · **Чек** · синя **Зберегти** (Ctrl S) · значок історії з лічильником · закрити.
- **Друк ▾** містить: видаткову накладну, рахунок-фактуру, гарантійний талон, наклейку (PDF) і бланк замовлення. Для Rozetka Delivery
  замість наклейки — «Маркування Rozetka» (PDF з API Rozetka).

- **Товари — компактні:**
  - рядок **46 px**: фото 34 px · назва · варіант списком-пігулкою («● Чорний ▾») · артикул і залишок дрібно · кількість − 1 + · сума · ×;

### 5.5 «Що лишилось»
Кроки, яких бракує саме цьому замовленню. Показуються лише ті, що стосуються замовлення, і самі
відмічаються, коли зроблені. Клік по невиконаному кроку виконує дію.

| Пункт | Коли є в списку | Дія по кліку |
|---|---|---|
| Товар зарезервовано | завжди після «Прийняти»; червоний, якщо не вистачає | замінити варіант або створити закупівлю |
| Передоплата надійшла | є передоплата або повна оплата | позначити оплаченою |
| Чек на передоплату | є передоплата і каса Checkbox | пробити чек |
| ТТН створено | доставка перевізником | створити ТТН |
| Наклейку надруковано | є ТТН | друкувати |
| Накладну в посилку надруковано | увімкнено в «Налаштування → Документи» | друкувати видаткову |
| У реєстрі НП | є ТТН НП | додати в реєстр |
| SMS з ТТН надіслано | є ТТН і шаблон | надіслати |

Після відправки список змінюється на три пункти: Покупець забрав · Гроші надійшли · Чек післяплати
пробито. Їх відмічає трекінг.

### 5.6 Вікно створення ТТН
Макет: `03-vikno-ttn.png`. Вікно 1000 × 720 поверх списку.

Поля ліворуч:
- відправник — ключ НП;
- отримувач — з замовлення, лише читання;
- спосіб доставки: Відділення · Поштомат · Кур'єр;
- місто й відділення з пошуком по довіднику НП (видно обмеження ваги);
- хто платить: Отримувач · Відправник · Третя особа;
- тип вантажу, вага, розміри, кількість місць;
- оголошена вартість;

### 5.7 Залежності полів
Поле, що заповнилося саме, має під собою синій підпис джерела. Якщо змінити значення вручну,
підпис стає «змінено вручну · повернути».

| Що ввели | Що заповнюється саме |
|---|---|
| Телефон | покупець, історія, викуп, чорний список, дублі, ПІБ |
| Джерело | відділ |
| Товар → варіант | ціна, артикул, залишок, вага й розміри для ТТН, допродаж |
| Юрособа | каса Checkbox, ключ НП, реквізити документів |
| Оплата + передоплата | сума при отриманні, тип післяплати в ТТН, чек на передоплату |
| Статус | резерв або списання, SMS, чек, статус у Rozetka / Prom |

### 6.1 Що має зберігати база
Зараз документи будуються з поточних даних і не записуються. Тепер **кожен виданий документ — окремий запис**:

| Поле | Навіщо |
|---|---|
| тип: видаткова / рахунок-фактура / гарантійний талон | три кнопки й їхній стан |
| номер і дата | нумерація окрема для юрособи й типу, з префіксом із налаштувань; номер не використовується повторно |
| юрособа, замовлення, покупець, сума | вкладки, фільтри, підсумок |
| знімок даних на момент видачі (реквізити, товари, ціни, гарантія) | документ через рік виглядає так само |
| стан: чинний / анульований + посилання на нову версію | перевипуск не стирає старий документ |
| хто й коли створив, скільки разів друкували | журнал дій і «Що лишилось» |

Коли документ створюється:
- видаткова й гарантійний талон — самі, коли замовлення стає «Відправленим», або при першому друці, якщо він був раніше;
- рахунок-фактура — лише кнопкою.

Момент створення налаштовується в «Налаштування → Документи».

## 10. Головна (під наш функціонал)

## 19. Що вже працює в CRM і не має загубитися в новому вигляді

Новий інтерфейс — це новий вигляд тих самих функцій. Перед злиттям кожного кроку перевірити, що нічого з переліку не зникло.

- **Нова Пошта:** кілька ключів (`NpAccount`), кожен з відправником і типовими параметрами ТТН; правила «код статусу ТТН →
  статус замовлення» (`NpStatusRule`); трекінг; реєстр; перевірка оплати в ТТН.
- **Checkbox:** каса на кожну юрособу, вибір каси `pick_cashier()`, чеки продажу, повернення, передоплати й післяплати —
  автоматично за статусами або кнопками; масова «Фіскалізувати».
- **Маркетплейси:** імпорт з Rozetka / Prom кожні 5 хв, мапи статусів, оплат і доставок, передача статусу назад;
  Rozetka Delivery з маркуванням.
- **Довідники:** 47 видів оплат зі значками, відділи й джерела, причини, позначки зі значком і кольором, поля 1–4 (вмикаються).
- **Юрособи:** реквізити, каса, ключ НП, документи (видаткова, рахунок-фактура, гарантійний талон, префікси, логотип, умови гарантії).
- **Замовлення:** ПІБ одним рядком з розпізнаванням, ТТН з нового замовлення без окремого збереження, допродаж під товаром,
  нагадування, коментарі колегам, журнал дій, дублювання, SMS / Viber / Telegram за статусами.
- **Товари:** категорії з вкладеністю, бренди, країни продажу, фото, атрибути й варіанти зі своїм SKU і залишком, архів замість видалення.
- **Покупці:** за телефоном, групи, сума, відмови, чорний список (попередження в картці, позначка в списку, блок IP у webhook).
- **Статистика й головна:** усі показники етапу 5 і `GET /api/dashboard` (розділи 10–11).
- **Класичний інтерфейс `/classic`** і webhook прийому заявок — без змін.
